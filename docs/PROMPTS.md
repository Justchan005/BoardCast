# Prompts and their context

Every prompt is a versioned Markdown file in `prompts/`. Code loads it by name, and the version is written to the run trace with each call.

| Prompt | Used by | Context the model receives | Why it is written this way | How its output is checked |
| --- | --- | --- | --- | --- |
| `extract.md` v2 | `backend/extract.py` | The poster image, the item type, the current year | "Copy what is printed, null if absent" removes guessing. v2 added rules for teaser lines and co-hosts after v1 missed 4 of 103 fields | Pydantic schema, one retry, QR links decoded in code, required-field check, the club confirms |
| `prereview.md` v1 | `backend/prereview.py` | One JSON object: fields, description, `has_poster`, `poster_fields`, `links`, problems already found by code, today's date | Lists each tool with the condition for calling it, so the model chooses per submission. States that club text is data | Function calling in ANY mode, argument validation, each tool once, turn and tool limits, fixed rules applied afterwards |
| `verify.md` v1 | `verify_against_poster` tool | The poster image and only the submitted fields being checked | A second reader with a different prompt catches the first reader's mistakes and the club's typing mistakes | Schema, only requested fields kept, date/time mismatches re-compared in code |
| `editor.md` v4 | `backend/editor.py` | Approved items as JSON | Returns only an event id, so no model prose can reach students | The id must be an approved event, otherwise code picks the earliest |
| `coordinator.md` v1 | ADK chat root agent | The user's message | Routes only; has no tools | Sub-agent tool lists; server-side role checks |
| `intake.md` v8 | ADK chat, club reps | Message and attached poster | One question at a time; never invents a fact; exact attachment filename | Same API checks as the web form |
| `review.md` v3 | ADK chat, Student Affairs | Reviewer's message | Confirms the title before deciding; never invents a rejection reason; v3 adds the acknowledgement step | Server refuses approval past unacknowledged red flags |

## Version history kept as evidence

- `eval/results/extract_v1.md` and `extract_v2.md`: field accuracy on the same 14 real APU posters before and after the prompt change. This is a development set, not a held-out estimate.
- `docs/evidence/output_checks.md`: normal, difficult, missing-data and failure cases with expected and actual results. Generated by `python -m eval.output_checks`.
- `docs/evidence/run-log-*.md`: one input linked to every action and the final result.
